# ADR/ — 設計判断の記録（Architecture Decision Record）

重要な設計判断を **1件1ファイル** で残す場所です。
残すのは「何を選んだか」だけでなく、**なぜそう決めたか**と**何を採らなかったか**です。

他のドキュメントとの使い分けは次のとおりです。

| 置き場所 | 書くこと |
|---|---|
| [`../spec/`](../spec/) | 現時点で実装されている動作（As-Is） |
| [`../requirements/`](../requirements/) | こうあるべき、という要件（To-Be） |
| [`../refactoring/`](../refactoring/) | 課題の洗い出しと、改善の進め方 |
| `ADR/`（ここ） | 迷った点について、**何を選び、なぜそうしたか** |

## 何を書くか

後から見て「なぜこうなっているのか分からなくなりそうな判断」です。

- 技術・ライブラリの選択（採用する／しない）
- データモデルの方針（テーブルを足す・廃止する、など）
- 仕様上の線引き（ステータスの分け方、など）
- 非機能の方針（キャッシュ、キュー、更新方式、など）

実装の細かい手順、バグ修正、一時的なメモは書きません。

## ルール

1. **1件 = 1判断。** 5分で読める量にします。
2. **ファイル名は連番＋短い題名。** `0004-xxxx.md`。番号は変えません。
3. **確定していないことは書きません。** 決まっていない点は Status を `Proposed` にし、`Decision` を「未決定」のままにします。選択肢の整理は書いて構いません。
4. **Accepted にしたら書き換えません。** 方針が変わったら新しい ADR を書き、古いものの Status を `Superseded by ADR-XXXX` にします。誤字や参照リンクの修正は例外です。
5. 新規作成は [`0000-template.md`](./0000-template.md) をコピーして使います。

## Status の意味

| Status | 意味 |
|---|---|
| Proposed | 検討中。決定していない |
| Accepted | 合意して採用した |
| Rejected | 検討の結果、採用しないと決めた |
| Deprecated | 当時は有効だったが、今は使わない |
| Superseded by ADR-XXXX | 新しい ADR に置き換えられた |
