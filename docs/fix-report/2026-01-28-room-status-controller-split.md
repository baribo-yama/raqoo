## 修正レポート

### 概要
ユーザー向けステータス取得APIが管理者ログイン状態の影響を受け、ユーザー表示が管理者ロジックで上書きされる問題に対応した。管理者用とユーザー用のコントローラーを分離し、ユーザーAPIは常にユーザー判定のみを行うように変更。

### 発生していた問題
- 同一ブラウザで管理者とユーザーを併用すると、ユーザー画面の表示が管理者ロジックに切り替わる
- 自分の申請中が「利用可能」のままになる
- 他人の予約が「利用不可」ではなく「予約済み」として表示される

### 原因
`/user/room-status` が管理者用 `RoomStatusController::getStatus()` を共用し、内部で `Auth::guard('admin')->check()` を優先していたため、管理者セッションが存在する場合にユーザー判定が無効化されていた。

### 修正内容
- ユーザー専用コントローラーを新規追加し、ユーザーAPIを専用化
- 管理者用 `getStatus()` は管理者専用ロジックのみで動作するよう整理
- ルーティングをユーザー用コントローラーに切り替え

### 変更ファイル
- 追加: `raqoo/app/Http/Controllers/User/RoomStatusController.php`
- 更新: `raqoo/app/Http/Controllers/Admin/RoomStatusController.php`
- 更新: `raqoo/routes/web.php`

### 動作確認手順
1. 同一ブラウザで管理者ログインとユーザーログインを併用
2. ユーザー画面で予約申請を実施
3. 申請中は「申請中」、承認後は「予約済み」と表示されること
4. 他ユーザーの予約は「利用不可」と表示されること

### 補足
ユーザー向けAPIは管理者セッションの有無に影響されない設計とし、責務分離を明確化した。
