## 3. 認証・アカウント

### 3.1 一般ユーザーのログイン

- `/login`：メールアドレスとパスワードによるログイン（`LoginController`）。成功時は `/home`（または直前に開こうとしたページ）へ進み、失敗時は「メールアドレスまたはパスワードが違います」と表示します。
- ログイン画面には「Googleでログイン」ボタンと「Googleログインは学校のアカウントで行ってください」という案内があります。
- `/logout`（POST）：セッションを無効化し、`/login` へ戻します。
- レート制限はありません。

### 3.2 Google ログイン

- `/auth/google/redirect` で Google へ遷移し、`/auth/google/callback` で戻ります。
- 許可ドメイン（メールアドレスの末尾一致）：`@edu.sba.ac.jp` / `@edu.ssm.ac.jp` / `@sba.ac.jp` / `@ssm.ac.jp`。
- 許可外なら「学校のアカウントでログインしてください」と表示して `/login` へ戻します。
- `google_id` でユーザーを検索し、存在しなければメールアドレスのみで作成します（パスワードは null）。
- ログイン後、学籍番号が未登録なら `/signup` へ、登録済みなら `/home` へ進みます。
- 設定は環境変数 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI` です。

### 3.3 新規登録（`/signup`）

- 入力項目は名字・名前・学籍番号（ユニーク）です。メールアドレス欄はログイン中ユーザーのアドレスを読み取り専用で表示します。
- 専攻の入力欄はコメントアウトされています。
- 送信時にメールアドレスのドメインを再チェックし、ログイン中のユーザー情報を更新して `/home` へ進みます。
- ⚠ GET と POST の `/signup` は、どちらも `auth` ミドルウェアの外にあります。

### 3.4 管理者のログイン

- `/admin/login`：メールアドレス、パスワード、「ログイン状態を保持」（remember me）。成功時は `/admin/dashboard` へ進み、失敗時は「認証情報が正しくありません。」と表示します。
- ログイン画面にはユーザー画面へのリンクがあります。Tailwind v2 を unpkg CDN から読み込んでいます。
- `/admin/logout`（POST）：`/admin/login` へ戻します。
- ⚠ `admins` テーブルに `remember_token` の列がないため、「ログイン状態を保持」にチェックしてログインすると SQL エラー（500）になると考えられます。

### 3.5 Breeze 由来の機能（`routes/auth.php`）

- register、パスワードリセット、メール認証、パスワード確認のルートが残っています。
- `/login` と `/logout` は、`web.php` 側の定義で上書きされています。
- メール認証は無効です（`User` の `MustVerifyEmail` がコメントアウト）。
- ⚠ `/register` は公開されたままです。`RegisteredUserController` は存在しない `name` 列に書き込むため、送信すると 500 になります。ドメイン制限もかかりません。
- ⚠ `/forgot-password` などのパスワードリセットにも到達できます。Google のみで登録したユーザー（パスワードが null）への適用可否は決まっていません。

### 3.6 セッション

- ドライバは `database`、有効期限は `.env` の `SESSION_LIFETIME=120`（分）です。
- ⚠ `config/session.php` の既定値は `2`（分）です。`.env` に `SESSION_LIFETIME` がない環境では、2 分でセッションが切れます。

## 4. 利用可能時間（TimeGuard）

- 対象ルート：`/home`、`/reservations/create`、`/reservations/check`、`/reservations`（POST）。
- 平日は 9:10〜19:30、土日は 10:50〜17:50 の範囲だけ利用できます（境界の時刻を含む）。
- 範囲外なら `/unavailable` へリダイレクトします。表示内容は次のとおりです。
  - 「現在の時間は、予約申請を受け付けておりません。お手数ですが、明日以降に申請をお願いいたします。」
  - 「月～金曜日：9:10～19:30」「土・日・長期休暇期間：10:50～17:50」
- ⚠ 長期休暇・祝日の判定はありません（祝日も平日として扱います）。
- 予約一覧・詳細・キャンセル・履歴・お知らせ・`/user/room-status`・`/user/my-reservations` には TimeGuard がかかっていないため、時間外でも利用できます。
- `TIME_GUARD_ENABLED=false` で無効化できます（既定は有効）。
- 本番以外の環境では、`APP_FAKE_NOW` を設定するとアプリ全体の現在時刻をその値に固定できます。

## 5. ユーザー画面

### 5.1 共通：サイドバー

- メニュー：ホーム / 予約一覧 / 利用履歴 / 利用規約 / お知らせ / ログアウト。
- 未読のお知らせがあると「!」バッジを表示します。
- 現在の URL と完全一致、または前方一致するメニューを自動で選択状態にします。
- 1024px 以下ではハンバーガーメニューになります。外側のタップ、背景のタップ、Esc キーで閉じ、PC 幅に戻すと自動で閉じます。

### 5.2 ホーム（`/home`）

**表示**

- プロフィール欄：学籍番号（未設定なら「未設定」）と氏名。
- 成功・エラー・info のフラッシュメッセージ。

**検索フォーム**（GET でページを再読み込み）

- 項目：日付、利用時限（開始〜終了、各「指定なし」と 1〜6 限）、利用人数。
- 14 日より先の日付なら「予約できるのは2週間先までです。」と表示します。
- 開始時限が終了時限より後なら自動で入れ替え、「開始時限が終了時限より遅いため、自動的に順序を入れ替えました。」と表示します。
- 人数を指定すると、定員がその人数以上の教室に絞り込みます。
- 日付と開始・終了時限をすべて指定すると、その範囲に `room_statuses` で `available` 以外の行がある教室を除外します。⚠ 予約テーブル・授業テーブルは見ていません。
- 階数チップ：「すべて」「1F」〜「5F」。1〜5 以外の値は無視します。

**日付ストリップ**

- 7 日分のタブ、前後の矢印（1 日ずつ移動）、日付入力欄があります。
- 日付を変更すると `/user/room-status?date=…` を Ajax で取得し、カードの状態を更新します。予約リンクの `date` パラメータも書き換えます。
- 定期的な自動更新はありません。最新状態にするには、日付を選び直すか再読み込みが必要です。

**教室カード**

- 教室ごとに教室名と定員、時限ごとのカード（時刻、階、状態）を表示します。時限を指定した場合はその範囲だけ表示します。
- 状態の表示：

| ステータス | 表示 |
|---|---|
| `available` | 「利用可能」＋「予約する」 |
| `pending` | 申請中 |
| `reserved` | 予約済み |
| `in_use` | 利用中 |
| `unavailable` | 利用不可（授業がある場合は授業名） |
| `conflict` | 同時刻に予約あり |

- `available` 以外のカードはリンクを外し、`aria-disabled` にします。
- 「予約する」を押すと注意事項（`/precautions?next=予約フォームのURL`）へ進みます。
- ⚠ サーバー側の初期描画では判定用のデータを渡していないため、いったん全カードが「利用可能」で描画され、その後 JS の取得結果で上書きされます。

**ステータス判定（`/user/room-status`、上から順に優先）**

1. 授業あり → `unavailable`（授業名つき）
2. 自分の `pending` / `reserved` / `in_use` の予約 → そのステータス
3. 他人の `reserved` / `in_use` の予約 → `unavailable`
4. 空いていて、同じ日の同じ時限に自分の予約（別教室）がある → `conflict`
5. 当日で、その時限の終了時刻を過ぎている → `unavailable`（1〜4 の結果を上書き）
6. いずれにも当たらない → `available`

- ⚠ 他人の `pending` は `available` に見えます（申請時にサーバー側で重複として弾かれます）。

**スマホ（560px 以下）**

- 「予約状況を見る」ボタンでボトムシートを開き、選択中の日付の自分の予約を `/user/my-reservations` から取得して表示します。
- 並び順：予約済み → 申請中 → その他。各予約に教室・日付・時限（時刻）・ステータスと「詳細を見る」リンクを表示します。
- 予約がない場合は「この日の予約はありません」、取得に失敗した場合は「取得に失敗しました」と表示します。

### 5.3 注意事項（`/precautions`）・利用規約（`/terms`）

- 3 ステップのカード形式です。
  1. **空き時間を確認・選択する：** 申請可能時間は平日 9:10〜19:30、土日 10:50〜17:50。2 名以上なら 1 教室につき 2 コマまで。
  2. **申請フォームを入力して送信する：** 利用目的・代表者・利用メンバーを入力。承認・却下の結果はアプリの「お知らせ」に届く。
  3. **当日・受け取りと返却：** 利用開始 10 分前に受付で鍵を受け取る。全員分の学生証を提出し、鍵の返却時に返却される。利用後は速やかに退室・返却・清掃する。
- 操作：スマホは左右スワイプ（50px 以上）と矢印ボタン、PC はカード左右のクリックエリアと ←/→ キー。ドットで任意のステップへ移動できます。
- `/precautions`（同意モード）：
  - 全ステップを表示するまで「同意して予約へ進む」ボタンは押せません（表示済みのステップは sessionStorage に保存）。
  - 「次回からこの注意事項を表示しない」にチェックして同意すると、同じセッション中は `next` 付きのアクセスで注意事項を飛ばします。
  - 同意すると、同意日時をセッションに保存して `next` へ進みます。
  - `next` は `/` で始まる内部パスだけ許可します（`//` 始まりや絶対 URL は拒否してホームへ）。
- `/terms`：同じ画面を、同意ボタンなしで表示します。

### 5.4 夜間注意事項（`/night-precautions`）

- 3 ステップの案内ページのみです。ナビゲーションからのリンクはなく、予約機能とも連動していません。
  1. **対象と条件：** 利用可能時間は金曜 19:40〜翌 6:00。学年ごとの利用は不可（教員の許可が必須）。全員分の氏名を事前に記入。6:00 には完全退出。
  2. **事前準備と申請提出：** 予約申請書を事前に提出。使用目的と終業を明記。教員のサイン（捺印）が必須。使用する教室に〇をつける。
  3. **利用当日のルール：** PASS 証を携帯。使用教室以外への立ち入り禁止。宿泊・仮眠禁止。利用後は速やかに退出・清掃・報告。

### 5.5 予約フォーム（`/reservations/create`）

**フォームを開く前のチェック**（不合格ならホームへ戻してエラー表示）

1. 今日、自分の有効な予約（`pending` / `reserved` / `in_use`）があり、まだ終了していない → 「今日の予約の利用が終了してから新たに予約してください」。⚠ 選択日が今日の場合、時限に関係なく新規予約をブロックします。
2. 選択した時限が今日すでに終了している → 「選択された時限はすでに終了しています。…」
3. 明日以降の日付で、その日に自分の有効な予約がある → 「1件すでに予約が入っているのでできません」（1 日 1 予約）
4. 教室が存在しない → 「教室がみつかりません。」
5. 14 日より先 → 「予約できるのは2週間先までです。」

**表示・入力項目**

- 基本情報：教室、日付、選択中の時限、設備。
- 代表者：専攻（⚠ 常に空）、氏名、学籍番号。
- 利用目的：必須、100 文字以内、文字数カウンターあり。
- 利用メンバー（代表者以外）：最大 30 名。初期表示は 5 行で、「5名追加」ボタンで 5 行ずつ増やせます。1 人 50 文字以内。空欄は送信せず、改行区切りでまとめて送信します。
- 連続予約（オプション）：
  - メンバーが未入力（1 名利用）なら追加の時限は選べません（「※1名利用（メンバー未入力）の場合は連続予約できません。」）。
  - メンバーがいる場合、選択中の時限の直前または直後の 1 コマだけ追加できます（最大 2 コマ）。
  - 授業や他の予約がある時限は「(授業)」「(予約済)」と表示し、選択できません。
- 「キャンセル」でホームへ戻り、「確認画面へ」で確認画面へ進みます。

### 5.6 確認画面（`/reservations/check`）・保存（`/reservations`）

**確認画面の検証**

- 教室が存在すること、日付が今日以降であること、時限が 1〜2 個で値が 1〜6 であること、利用目的が必須で 100 文字以内であること。
- 終了済みの時限を含まないこと、時限が連続していること。
- 他人の有効な予約や授業と重なっていないこと（「選択された時間帯の中に、すでに予約済みまたは授業が登録されている枠が含まれています。」）。

**確認画面の表示**

- 教室、階、日付、時限、収容人数、設備、利用目的、代表者、利用メンバー。
- 「修正する」で予約フォームへ戻り、「申請を確定する」で保存します。

**保存の処理**

- 確認画面と同じ検証（終了済み時限、連続性）を再実行します。
- トランザクション内で、次の重複チェックをします。
  - 他人のキャンセル以外の予約（`pending` を含む）、または授業と重なる → 予約フォームへ戻し「タッチの差でほかの予約か授業で教室が埋まってしまいました。」
  - 同じ時限に自分の別教室の予約がある → 「同時刻にすでにあなたの予約があるため予約できません」
- 時限ごとに `status = pending` の行を作成し、ホームへ戻して「予約申請を送信しました。承認をお待ちください。」と表示します。
- 管理者への通知はありません。

### 5.7 予約一覧（`/reservations`）

- 今日以降の自分の予約を、日付・時限の順に表示します（全ステータス）。
- 表示項目：教室、ステータス、日付（曜日つき）、時限、利用目的（20 文字まで）、申請日。各予約から詳細へ遷移できます。
- 予約がない場合は「予約がありません」と「教室を予約する」ボタンを表示します。

### 5.8 予約詳細（`/reservations/{id}`）・キャンセル

- 本人の予約以外は 403 にします。
- 表示項目：ステータス、教室、階、日付（曜日つき）、時限、収容人数、設備、利用目的、代表者、利用メンバー、申請日時。
- ステータスが `pending` / `reserved` のときだけ「予約をキャンセル」ボタンを表示します。確認モーダル（「この操作は取り消すことができません。」）を経て、`status` を `cancelled` に更新します。
- キャンセルでは `room_statuses` を更新しません。
- ⚠ ステータスバッジは `approved` / `rejected` を前提にしているため、`reserved` のときはバッジが表示されません。却下理由の表示欄もありますが、列がないため表示されません。

### 5.9 利用履歴（`/reservations-history`）

- 対象：過去の日付の予約、または `finished` / `cancelled` の自分の予約。新しい日付順に 10 件ずつページングします。
- 表示項目：教室、ステータス、日付（曜日つき）、時限、申請日、人数、利用目的。
- ⚠ バッジは `completed` / `rejected` を前提にしているため、`finished` のときはバッジが表示されません。

### 5.10 お知らせ（`/notifications`）

- 開いた時点で、自分の未読のお知らせをすべて既読にします。
- 新しい順に 10 件ずつページングし、時刻（H:i）と日付（m/d）、本文を表示します。
- ⚠ すべてのお知らせに「重要」バッジが固定で表示されます。
- ⚠ キーワード検索フォームはありますが、サーバー側の検索処理はありません。

### 5.11 その他のユーザー向けルート

- `/user/my-reservations`：自分の予約の JSON。`date` で絞り込みでき、省略時は今日以降。`limit` は最大 100（既定 50）。
- `/unavailable`：利用時間外の案内（4 章を参照）。
- ⚠ `/info` は存在しないビュー `user.info` を参照しているため 500 になります。
- ⚠ `/`（トップページ）のルートはなく、404 になります。

## 6. 管理者画面

すべて `auth:admin` で保護されています。

### 6.1 ダッシュボード（`/admin/dashboard`）

**教室状況**

- 月カレンダー（前月・翌月の切り替え、今日と選択日を強調）で日付を選ぶと、その日の「教室×時限」の表を `/admin/room-status` から Ajax で取得します。
- 授業のセルは灰色で授業名、`reserved` / `in_use` の予約のセルは青で「予約」と表示します。申請中（`pending`）は表示しません。

**セルをクリックしたとき（モーダル）**

| セルの種類 | 表示 | 操作 |
|---|---|---|
| 空き | 授業名の入力欄 | 「登録」で授業を登録（同じ枠に既存があれば上書き） |
| 予約 | 代表者名とメンバー | 「予約キャンセル」で予約を **物理削除**（`room_statuses` は更新しない） |
| 授業 | 授業名 | 「授業キャンセル」で授業を削除 |

**予約リクエスト（承認待ち一覧）**

- `pending` の予約を「同じユーザー・同じ日付・同じ教室・同じ利用目的・同じメンバーで、時限が連続しているもの」でまとめ、1 申請として表示します。
- 表示項目：専攻（⚠ 常に空）、学籍番号、教室、予約日、時限（範囲）、利用目的。
- 申請ごとに「承認」（一括承認）と「却下」（一括却下）のボタンがあります。

**🔔 バッジ**

- 上記と同じまとめ方での申請数を、`/admin/reservations/count` から 30 秒ごとに取得して表示します（0 件なら非表示）。

### 6.2 承認・却下の処理

| 操作 | 入口 | 予約のステータス | `room_statuses` | お知らせ | メール |
|---|---|---|---|---|---|
| 一括承認 | ダッシュボード | `reserved` | `reserved` に更新 | 申請単位で 1 件（「予約（全Nコマ）が承認されました。教室 - 日付 時限」） | 送らない |
| 一括却下 | ダッシュボード | `cancelled` | 更新しない | 申請単位で 1 件（「予約（全Nコマ）が却下されました。…」） | 送らない |
| 単体承認 | 予約管理画面 | `reserved` | `reserved` に更新 | 1 件（「予約が承認されました。…」） | 承認メール |
| 単体却下 | 予約管理画面 | `cancelled` | 更新しない | 1 件（「予約が却下されました。…」） | 却下メール |

- 対象は `pending` の予約だけです。それ以外は「承認待ちの予約が見つからないか、既に処理されています。」または「この予約は承認待ちではありません。」と表示します。
- 一括操作はトランザクション内で処理し、単体操作はトランザクションを使いません。
- 管理者による却下と、ユーザー自身のキャンセルは、どちらも同じ `cancelled` になります。却下理由は入力できません。
- ⚠ 承認メールはビュー名の綴りミス（`emails.reservation-approveed`）のため、送信時に例外（500）になると考えられます。

### 6.3 メール

| 種類 | 件名 | 本文 |
|---|---|---|
| 承認 | 【Raqoo 教室予約管理システム】予約が承認されました | 教室、日付、時限、「予約一覧を確認する」ボタン |
| 却下 | 【Raqoo 教室予約管理システム】予約が却下されました | 見出し「予約申請が却下されました」、教室、日付、時限、「予約一覧を確認する」ボタン |

- 同期送信です（キューは使いません）。
- `MAIL_MAILER` の既定値は `log` のため、開発環境ではログへの出力のみです。本番用の Gmail SMTP 設定例は `.env.example` にコメントで書かれています。
- 「予約一覧を確認する」ボタンのリンク先は `/reservations`（ユーザーの予約一覧、要ログイン）です。管理者用は `/admin/reservations` で別のルートです。

### 6.4 その他の管理者画面・API

- 予約管理（`/admin/reservations`）：`pending` の予約を 1 行ずつ一覧表示します（申請者、教室、日付、時限、目的）。各行に「承認」と「却下」（確認ダイアログあり）のボタンがあります。
- 教室管理（`/admin/rooms`）：ID と教室名の一覧表示のみです（編集機能はありません）。
- ⚠ `/admin/notifications`：参照しているビュー `admin.notifications-index` が存在しないため 500 になります。
- `POST /admin/room-status`：`room_statuses` を直接書き換える API です。画面からは使われていません。

| ログ | `stack` → `single`（`storage/logs/laravel.log`） |
| スケジューラ | `routes/console.php` は標準の `inspire` コマンドのみ。⚠ `in_use` / `finished` への自動遷移はない |
| テスト（`phpunit.xml`） | SQLite インメモリ、メールは `array`、キューは `sync`、セッションは `array` |
